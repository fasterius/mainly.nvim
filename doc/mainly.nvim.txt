 1. INTRODUCTION                                        *mainly.introduction*

 When working with Nextflow pipelines, many files are named `main.nf` by
 convention: one per module, subworkflow and pipeline. In a statusline showing
 just the filename, they're indistinguishable. `mainly.nvim` fixes this by
 giving each `main.nf` (and `main.nf.test`) a contextual label based on its
 parent component or pipeline name, for use in your statusline:

==============================================================================

 2. REQUIREMENTS                                        *mainly.requirements*

 - Neovim >= `0.11.0`

 `mainly.nvim` has no dependencies on other plugins. It is commonly paired
 with a statusline plugin (_e.g._ lualine.nvim
 (https://github.com/nvim-lualine/lualine.nvim)), but that is optional; see
 |mainly.usage|.

==============================================================================

 3. USAGE                                                      *mainly.usage*

 `mainly.nvim` exposes two Lua functions, meant to be called from your own
 configuration rather than interactively.

 setup({opts})                                               *mainly.setup*

   Configures the plugin. Optional -- the defaults are used if `setup()`
   is never called. `{opts}` is validated and merged with the defaults;
   see |mainly.configuration| for the available keys.
>lua
     require("mainly").setup({
         allowed_sources = { "local", "nf-core", "my_source" },
         include_component = true,
     })
<
 filename()                                               *mainly.filename*

   Returns the formatted label (a string) for the current buffer, to be
   used as the filename component of a statusline. Files other than
   `main.nf` or `main.nf.test` (or components with a source not present in
   |mainly.allowed_sources|) fall back to the buffer's plain filename.

   This is the function meant for statusline integration, illustrated
   here for [lualine.nvim](https://github.com/nvim-lualine/lualine.nvim):
>lua
     local mainly_filename = require("mainly").filename
     require("lualine").setup({
         sections = {
             lualine_c = { mainly_filename },
         },
         inactive_sections = {
             lualine_c = { mainly_filename },
         },
     })
<
   Since it returns a plain string, it can be used with any statusline
   plugin, or Neovim's built-in 'statusline'.

==============================================================================

 4. CONFIGURATION                                      *mainly.configuration*

 allowed_sources (default: `{ "local", "nf-core" }`) *mainly.allowed_sources*

   The allowed sources for components, used to validate the component found in
   a file's path (_e.g._ the `nf-core` in `modules/nf-core/fastqc/main.nf`).
   Components with a source not in this list fall back to the plain filename
   in |mainly.filename|.

 include_component (default: `false`)              *mainly.include_component*

   Whether to prefix the label with `<kind>/<source>/`, _i.e._ the full
   component path, instead of just `<name>/main.nf`.

==============================================================================

 5. HEALTH                                                    *mainly.health*

 `mainly.nvim` integrates with |:checkhealth|; run `:checkhealth mainly`
 to check:

 - That the running Neovim version satisfies |mainly.requirements|.
 - That the current configuration (set _e.g._ via |mainly.setup|) contains no
   unrecognised options.

==============================================================================

 6. KEYMAPS                                                  *mainly.keymaps*

 This plugin does not export any key mappings by default (:help
 lua-plugin-keymaps), nor does it define any that make sense to map yourself:
 |mainly.filename| is not an interactive action but a statusline-component
 function, meant to be wired up as shown in |mainly.usage| rather than bound
 to a key.
